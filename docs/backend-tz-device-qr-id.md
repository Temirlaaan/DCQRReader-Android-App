# ТЗ (баг): `data.qr_id` пустой для привязанных устройств

**Для:** бэкенд qr-dc (FastAPI-прослойка над NetBox)
**Инициатор:** мобильный клиент DC Inventory
**Приоритет:** средний (видно в карточке устройства, мешает приёмке)

## Симптом

В карточке устройства, открытой **не через скан** (вкладки «Стойки» и
«Устройства»), поле «QR-метка» показывает «Не привязана», хотя устройство
фактически привязано: в NetBox `custom_fields.qr_id` заполнен, а в реестре QR
метка в статусе BOUND с `bound_to_device_id` = этому устройству.

На экране **после скана** метка отображается корректно — там клиент берёт
отсканированный `qr.id` напрямую и от ответа устройства не зависит.

## Причина

В ответе `GET /api/v1/devices/{id}` верхнеуровневое поле `data.qr_id`
приходит `null` для привязанных устройств. Поле объявлено в схеме `DeviceData`
(`qr_id: string | null`), мобильный клиент его читает, но сервер его не
заполняет. В `custom_fields` этого ответа ключа `qr_id` тоже нет (проверено
по логам: `GET /devices/238` → `"qr_id": null`, в `custom_fields` только
cpu_model/os_name/… без qr_id).

## Что нужно

Заполнять `data.qr_id` человекочитаемым кодом метки (`DCQR-XXXXXXXX`) для
привязанных устройств в обоих местах, где отдаётся `DeviceData`:

1. `GET /api/v1/devices/{id}` (Read Device) — основной кейс.
2. `device.data` внутри `GET /api/v1/qr/{id}` (Lookup) — для единообразия.
3. Желательно и в `GET /api/v1/devices/search` (результаты списка), чтобы
   метку было видно прямо в списке вкладки «Устройства».

Источник истины — на усмотрение исполнителя, любой из:
- реестр QR: `qr_codes.id WHERE bound_to_device_id = {device_id} AND status='bound'`;
- либо `custom_fields.qr_id` из NetBox.

Для непривязанных устройств `qr_id` остаётся `null` (текущее поведение — верное).

## Acceptance

- `GET /api/v1/devices/{id}` для привязанного устройства → `data.qr_id` =
  `"DCQR-..."`.
- Для свободного устройства → `data.qr_id` = `null`.
- Мобильная карточка из «Стоек»/«Устройств» показывает метку без изменений
  на клиенте (клиент уже читает `data.qr_id` + фоллбэк на `custom_fields.qr_id`).

## Мобильная сторона

Менять ничего не нужно: клиент уже резолвит `data.qr_id`, фоллбэк на
`custom_fields.qr_id`, а на экране скана — отсканированный код. Как только
сервер начнёт отдавать `data.qr_id`, метка появится во всех карточках.
